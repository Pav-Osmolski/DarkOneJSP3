DarkOneJSP3 v0.9.29 Validation Report
=====================================

Scope
-----
This report covers the files evaluated by the bundled release validator. Its
scope includes package structure, runtime scripts, configuration and reset
behaviour, metadata, documentation and intentional compatibility mirrors. The
maintainer-managed DarkOneJSP3.fcl is deliberately excluded from inspection,
validation and the audited-file count.

Checks
------
- Bottom-area state is shared through js_data\darkonejsp3.bottom-area-state.txt
  so the three JScript Panel instances and the Bottom Controls JSplitter host do
  not depend on cross-component NotifyOthers delivery. Legacy state stored under
  DarkOneJSP3\shared is migrated automatically.
- JScript Panel state persistence uses the canonical two-argument
  `utils.WriteTextFile(path, content)` form. False returns and exceptions are
  logged with the target path, and failed bottom-area writes are retried once.
- Each JScript panel reads and applies the state once during initialisation,
  before its first paint, and uses same-component notifications for live peer
  updates. Repeated resize callbacks do not reread the file or query peers.
- Divider-only changes persist and update shared menus without rebuilding
  JScript control or Display visual resources.
- Only the Bottom Controls JSplitter polls continuously. Visible bottom-area
  state is checked at 100 ms, while the factory-reset command is checked at
  500 ms through the same timer and acknowledged after successful processing.
- Display/Waveform reads the shared bottom-area state once, defaults to
  Automatic Host background and receives state-only notifications relayed by
  Bottom Controls inside the JSplitter domain. Automatic custom and Columns UI
  modes are exercised without adding another poller; Transparent / inherit
  parent must resolve to the shared #181818 parent
  tone and paint the full host surface.
- A fresh JScript Panel instance is created after persisted colour changes and
  factory reset to verify restart persistence.
- Cross-host factory reset is exercised through
  js_data\darkonejsp3.reset-command.txt; Bottom Controls must consume the
  short-lived command and rebroadcast it to the other JSplitter controllers.
- Bottom-area painting covers the complete Bottom Controls host, including the
  lower Quick Search region and the narrow layout gaps beside both divider
  strips; Transparent / inherit parent resolves every bottom surface to #181818,
  while transparent dividers reveal that uniform backing.
- A complete six-mode matrix verifies that Transparent, Black, DarkOne grey,
  DarkOne dark grey, Columns UI and Custom resolve identically in the three
  JScript panels, the Bottom Controls host and Automatic Display/Waveform host.
- Album Art mouse-wheel bursts are coalesced through an 80 ms trailing timer,
  decode only the final selected artwork ID, persist that ID once, retain
  immediate keyboard selection and cancel pending work on metadata changes or
  script unload. Script unload also explicitly disposes active normal and blurred
  Direct2D bitmaps.
- The repository README contains a dedicated Enhanced Sample Library section
  and a direct link to the distributed ENHANCED_SAMPLES.txt guide.
- The complete user-components-x64 tree is staged without a DarkOneJSP3
  directory and every distributed top-level sample import resolves.
- Enhanced sample entries contain no hard DarkOneJSP3 profile-path imports.
- helpers.txt supplies guarded performance and UI-cadence compatibility for
  older saved JS Playlist and Smooth Playlist Manager entry scripts.
- Standalone sample defaults are separated from project-owned theme defaults;
  neutral and legacy reset notifications restore the same preserved properties.
- The generated legacy reset adapter is executed after the current project reset
  registry to reproduce saved entries created before the standalone-sample refactor across every sample role.
- Generic panel object-menu commands remain safe when optional colour support
  is not loaded, while both page-background option names remain supported.
- JS Playlist metadata-only refreshes, including inline star-rating edits,
  preserve and safely clamp the current viewport offset rather than
  recentering on the previously focused item.
- Required project, documentation, controller, loader, wrapper, sample and
  runtime bitmap files are present.
- Volume-knob cleanup uses the supported repaint-scheduler `cancel()` API and
  rejects invalid `stop()` calls on repaint schedulers.
- The volume knob uses the mouse-held drag state for its active highlight and
  clears that highlight immediately on button release; the Centre Display retains
  its independent three-second volume readout.
- Every scripted JSplitter and panel source declared by the layout manifest
  resolves to a distributed file; native-component entries are identified
  explicitly.
- Temporary, backup, empty and case-colliding package files are rejected.
- Build metadata and the layout manifest identify the same release version.
- Every fixed module version recorded by build metadata matches its maintained
  data-driven expectation.
- The validator entry point delegates to focused static and runtime check
  modules through a shared validation context.
- Required package paths and fixed module-version expectations are maintained
  as data rather than repeated conditional checks.
- Active scripts use the current DarkOneJSP3 namespace and supported panel
  titles.
- Local @import paths resolve inside the distributed package.
- JavaScript modules and active .txt entry scripts pass Node syntax checks;
  locally imported preprocessor sources are also combined and checked in their
  actual execution order.
- Demand-driven repaint schedulers coalesce requests, stop when idle and retain
  pending repaint work while a panel is hidden.
- Volume-knob dragging coalesces rapid mouse input, applies the first value
  immediately and flushes the exact final value on release.
- JS Playlist and Playlist Manager expose fixed and custom refresh intervals and
  announce their live values to the adaptive volume-preview protocol.
- Automatic volume-preview cadence follows the fastest reported panel interval
  with a 16 ms fallback, while manual 8/10/12/16 ms overrides remain available.
- Knob-preview and Centre Display repaint scheduling follow the resolved visual
  cadence, while actual fb.Volume writes retain a protected minimum 16 ms
  interval to avoid starving native visualisers.
- Trailing volume-state deadlines extend without clearing and recreating a timer
  for every on_volume_change callback.
- Dot Matrix volume output renders directly from the cached matrix sprite bitmap
  instead of rebuilding and disposing an off-screen volume bitmap during every
  drag update.
- JS Playlist render-cache tests cover repeated hits, row/handle/all invalidation,
  title-format changes, playback-generation reuse, clock-field overlays,
  cross-column $puts/$get compatibility and bounded cache size.
- Active playlist panels no longer contain permanent idle repaint intervals;
  Playlist Manager row type/lock flags and JS Playlist column geometry are
  cached.
- Album covers, immutable control sprites and display sprite output use reusable
  Direct2D bitmaps with explicit disposal checks.
- Centre Display style tests verify that Plain Font and Dot Matrix selections are
  persisted, rebuild style-specific render state and repaint immediately. Mutable
  dot-matrix value images compose from IJSImage sprite sources, while final panel
  painting retains cached IJSBitmap output.
- NumImage, TimeImage and BitrateImage explicitly inherit the shared BaseImage
  lifecycle and digit-comparison methods; runtime tests instantiate each class and
  exercise reset, bitmap commit, disposal and isDrawDigit behaviour.
- Native JScript Panel COM methods such as CreateBitmap, LoadBitmap, Dispose,
  CreateProfiler and profiler Reset are called directly rather than gated by
  typeof == "function".
- Python maintenance tools pass py_compile.
- Intentional compatibility mirrors remain synchronised; generated adapters
  match their canonical source inputs exactly.
- Every reset callback imports its registry and bridge dependencies.
- Coordinated resets use serialised payloads while retaining legacy payload
  compatibility; malformed scopes are rejected by standalone, JScript Panel
  and JSplitter receivers without applying defaults or reloading. Waveform
  blanking and reveal delay are validated as behaviour settings, while the Host
  background remains appearance-only.
- Startup settings remain owned by the root controller and preserve the tested
  reveal timing and first-layout safeguards.
- Biography, Last.fm, Album Notes, Properties and the optional scripted Queue
  Viewer use the shared Page background colour implementation and coordinated
  reset defaults.
- InfoStack, page, side-divider and waveform palettes preserve their documented
  defaults, saved mode values and Columns UI global-background behaviour.
- Shared colour conversion, parsing and Columns UI lookup are used by the
  consolidated colour implementations rather than duplicated local helpers.
- Shared JSplitter startup/divider protocols preserve notification names,
  message versions, saved values, property ownership and readiness behaviour.
- Shared left/right control-panel menu logic preserves optional-button IDs,
  command setup, command re-detection, DarkOne Tools access and button
  roundness behaviour while leaving panel-specific layouts local.
- InfoStack colour state and startup/divider bridge plumbing remain isolated in
  focused include helpers while layout, painting, menu IDs, saved properties and
  notification behaviour remain unchanged.
- Declarative menu mappings preserve the established menu-id-to-mode behaviour,
  including the legacy Custom mode positions.
- JSplitter and JScript Panel native colour-picker signatures are tested
  separately, including JScript Panel's error-on-cancel flag; cancellation
  preserves the existing mode and colour, while text
  entry remains an availability fallback only.
- InfoStack tab labels and the centre-display accent preserve their existing
  Default and Custom modes and can follow the Columns UI selected-item
  background colour.
- Upper-divider colour controls retain established geometry and remain
  independent from the lower control-divider settings.
- Bottom-area runtime tests isolate the JScript Panel and JSplitter notification
  domains, verify file-backed synchronisation for all three child panels and the
  host, cover every palette mode, transparent painting, full-host geometry,
  divider painting, Columns UI live updates and protocol serialisation.
- Album Notes provider settings, caching controls and embedded MusicBrainz
  settings are included in coordinated reset coverage.
- Managed AllMusic activation completes or fails closed without leaving a
  provider request indefinitely pending.
- JS Playlist scrollbar dragging uses a dedicated demand-driven latest-target
  frame loop with time-based interpolation. Runtime tests simulate 16 ms mouse
  callbacks and verify that 8 ms renders two distinct intermediate frames while
  16 ms renders one, with equal elapsed-time response and exact final snapping.
- Row-snapped and free-position dragging do not reuse the wheel-throttle timer,
  depend solely on mouse callback cadence or pass through a second repaint delay.
- JS Playlist general repaint requests use the selected smooth-scroll refresh
  interval, while interval-governed animation ticks use a coalesced immediate
  post-tick paint without generating extra frames.
- JS Playlist and Playlist Manager refresh, scrolling and appearance defaults
  are covered by the canonical registry.
- Smooth-scroll refresh-rate tests verify that both panels update their live
  rate values, persist the selected property and reschedule active animation
  timers or frame loops without reverting to the 8 ms default.
- The native Queue Viewer is identified as the recommended DOJSP3.Queue panel,
  while the optional scripted viewer is verified for multi-selection, keyboard
  navigation, source-item commands and the absence of unsupported mutation API
  calls.
- Playlist Manager clears all tracked timers during script unload.
- Public documentation uses current project identifiers and contains only the
  current package version outside CHANGELOG.txt.
- The Configuration Guide documents the principal user-facing menu surfaces
  in the supported layout, with selected labels checked against both source and
  guide so renamed or omitted menu entries fail validation.
- Native component-owned menus are identified explicitly rather than presented
  as DarkOneJSP3-owned settings.
- Documentation headings, numbered sections and README links are internally
  consistent; Configuration Guide headings require blank-line separation, and
  repository artwork is checked whenever an assets folder is present.
- Installation guidance distinguishes the default standard-install profile at
  %APPDATA%\foobar2000-v2\profile from both supported portable-profile
  structures and keeps the DarkOneJSP3 and user-components-x64 destinations
  explicit.
- Troubleshooting guidance describes current behaviour without development
  upgrade instructions.
- CHANGELOG.txt contains one document title and a correctly formatted entry for
  the current release.

Result
------
Run the bundled validator from the package root to reproduce these checks:

  python DarkOneJSP3\tools\validate_release.py .

DarkOneJSP3 Configuration Guide
===============================

This guide maps the user-facing DarkOneJSP3 menus and settings in the
supported layout. Native component menus can contain additional component-owned
commands; those are identified where they are outside DarkOneJSP3's control.

Menu notation
-------------

A path such as TOOLS > Startup means click the named optional button, then open
the listed submenu.

The exact place clicked matters in several panels:
- Playlist Manager: right-click a playlist row for playlist operations; right-
  click empty space or the scrollbar for appearance and scrolling settings.
- Main JS Playlist: right-click a track or empty playlist area for the main
  context menu; right-click the header bar for Groups, Columns and Double Track
  Line.
- Biography, Last.fm, Album Notes and Properties: right-click empty content
  space to open the panel-specific menu followed by shared page controls.
- Waveform: right-click the narrow JSplitter host/spacer for DarkOneJSP3 host
  settings; right-click inside Waveform Minibar for that native component's own
  menu.

1. Menu conventions and shared page controls
--------------------------------------------

Shared JScript Panel page controls
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The adapted information pages append common controls beneath their own
panel-specific commands.

Font size
~~~~~~~~~

Available when the panel contains text, list or display objects:
- 10
- 12
- 14
- 16

Colours
~~~~~~~

Available on Biography, Last.fm, Album Notes, Properties and the recommended
scripted Queue Viewer. Each panel instance stores its choice independently.

Enable Dynamic
^^^^^^^^^^^^^^

When enabled, the current artwork supplies the page background, text and
selection palette. Artwork changes, playback changes and playback stopping
refresh the palette automatically. Disabling Dynamic restores the page's saved
background, text and selected-background choices; those values are not
discarded while Dynamic is active.

Page background
^^^^^^^^^^^^^^^

Choices:
- Transparent / inherit parent
- Black
- DarkOne grey: RGB 32, 32, 32
- DarkOne dark grey: RGB 24, 24, 24 (default)
- Columns UI global background
- Custom colour (#RRGGBB)
- Set custom colour...

Selecting Custom colour immediately reapplies the remembered custom value. Use
Set custom colour... to edit that stored value with the native picker.

Transparent / inherit parent reveals the InfoStack backing colour. Columns UI
global background follows the active Columns UI background colour.

Text
^^^^

Choices:
- Default: follows the active Columns UI or Default UI text colour
- Custom: reapplies the remembered custom value
- Set custom colour...

Selected background
^^^^^^^^^^^^^^^^^^^

Available only in the recommended scripted Queue Viewer.

Choices:
- Default: preserves the original translucent selection highlight
- Custom: uses the remembered opaque selection colour
- Set custom colour...

Custom selected backgrounds automatically receive a contrasting text colour.
With Dynamic enabled, both selected background and selected text instead follow
the current artwork palette.

Background Wallpaper
~~~~~~~~~~~~~~~~~~~~

Available on Biography, Last.fm Biography, Album Notes, Properties, the two
combined image layouts and the recommended scripted Queue Viewer. Each panel
instance stores its wallpaper independently.

Choices:
- None (default)
- Front cover of playing track
- Custom image
- Custom image path...
- Blur

Front cover follows the currently playing track rather than the panel's
Selection mode. Custom image accepts either a complete image path or a path
relative to the foobar2000 profile directory. The wallpaper is cover-cropped
below the page header and painted at 10% opacity over the selected fixed or
Dynamic page background. Blur uses the same strength as Playlist Manager.

Wallpaper images refresh when playback or artwork changes. They remain in place
during the intermediate stop between tracks and are released when playback
fully stops, the wallpaper is disabled, the source is replaced or the panel is
unloaded. Hidden InfoStack pages defer image loading and blur until they next
become visible.

Combined image layouts
~~~~~~~~~~~~~~~~~~~~~~

Last.fm Bio + Images and Album Notes + Album Art add controls for their displayed
artwork before the content-specific commands:

- Display images / Display album art shows or hides the foreground image. When
  hidden, its complete region is returned to the text rather than left empty.
- Image background > Use displayed image as background independently draws the
  current artist or album image across the panel. Disable it to reveal the
  selected page colour or Background Wallpaper.
- Image background > Blur image background controls blur; Light, Medium and Dark
  select the backing-image shade.
- Image border selects None, Solid or Sunken. Default colour uses grey; Custom
  colour reapplies the remembered choice; Set custom colour... opens the picker.

Right-click the text region to restore a hidden foreground image. Right-click
the image region for layout/orientation and image-specific commands. Ctrl+wheel
over either region changes the image-to-text ratio.

Last.fm Bio + Images also provides Download now and Automatic downloads. With
Automatic downloads enabled, a visible panel using Prefer now playing requests
the playing artist when its local folder is empty. One request may be active at
a time, and failed or empty attempts use a maximum of three tries separated by
at least 30 seconds. Download now bypasses that waiting period; clicking it
again while the same artist request is active does not start a duplicate.

Before acquisition begins, an empty local folder is labelled `No images
downloaded`. While a Last.fm page or image-file request is active, the empty
image region centres `Downloading images...`. A temporary request or file
failure remains visible with a retry/error message, while a successful Last.fm
response with no usable images is reported as `No images available`. The
JScript Panel console records request starts, returned image counts, queued and
saved files, failures and the completion summary.

The downloader reads the normal Last.fm gallery structure first and can recover
current gallery URLs directly from the raw page markup if JScript Panel's DOM
conversion returns no usable nodes. A successful request that contains neither
a recognised gallery nor a confirmed-empty marker is labelled `Last.fm page
could not be read` and remains distinct from `No images available`.

Hide if no images available appears immediately below Download now. When
enabled, it returns the image region to the biography only after Last.fm has
successfully confirmed that no usable artist images are present. It does not
collapse the region for a network or parsing failure. Download now reveals the
region again while the manual retry is active.

Selection mode
~~~~~~~~~~~~~~

Available on panels that follow a media-library or playlist item:
- Prefer now playing
- Follow selected track (playlist)

Configure...
~~~~~~~~~~~~

Opens the current JScript Panel script editor/configuration window. It is an
advanced command; normal DarkOneJSP3 settings should be changed through the
menus documented here.

Album Art uses a related but separate Background colour menu because it is a
generic image panel rather than an InfoStack text page. See section 3.

2. DarkOne Tools and control panels
-----------------------------------

Opening the menus
~~~~~~~~~~~~~~~~~

DarkOne Tools opens only from an optional control-panel button configured as:

- Name: `TOOLS`
- Command: `DarkOneJSP3/Tools/Menu`
- Command style: `0` initially; the first successful use caches internal style 4

The popup is owned locally by whichever control panel contains the button and
opens directly beneath it. Right-click either control panel for its own Optional
buttons configuration. Right-click the centre display for Display Style and
Display accent colour only.

On the right control panel, right-click directly on the volume knob to open the
volume menu instead of the general control-panel menu.

Optional buttons
~~~~~~~~~~~~~~~~

Menu path: either control panel > Optional buttons

The submenu lists every optional button for that panel. Checked entries are
visible. The left panel provides eight optional buttons; the right panel
provides ten.

Additional commands:
- Edit buttons: configure command paths and display labels.
- Re-detect command types: clears remembered command classifications so they
  are detected again on the next click.
- Command guide...: explains supported main-menu, context-menu and trusted
  JavaScript command formats.

Optional-button settings are retained when a button is hidden. Labels are
limited to ten characters so they remain within the intended button area.

DarkOneJSP3 internal view commands:
- LAYOUT: `DarkOneJSP3/Layout/Toggle`
  Cycles the upper main area through InfoStack | ArtSpectrum | Playlist,
  ArtSpectrum | Playlist, InfoStack | Playlist (Playlist priority) and
  Expanded InfoStack | Playlist (InfoStack priority). In the first two-column
  InfoStack mode, InfoStack keeps its standard left-column width and Playlist
  consumes the remainder. In the second, Playlist keeps its standard right-
  column width and InfoStack consumes the remainder. Only horizontal allocation
  changes: InfoStack retains the same tab font, tab-area height and content
  height. The selected mode persists.
- SPECTRUM: `DarkOneJSP3/Visualiser/Toggle`
  Toggles DOJSP3.Spectrum. When hidden, Album Art receives the complete
  ArtSpectrum host. The selected mode persists.
- INFOSTACK: `DarkOneJSP3/InfoStack/Menu`
  Opens the InfoStack navigation/configuration menu aligned with the clicked
  optional button. The popup is owned by the invoking control panel and only
  the selected action is forwarded to InfoStack after it closes, avoiding
  disturbance to neighbouring native visualiser/waveform panels. This remains
  available when the visual tab strip is hidden.
- TOOLS: `DarkOneJSP3/Tools/Menu`
  Opens the shared DarkOne Tools menu locally beneath the clicked optional
  button. This is the sole DarkOne Tools launcher.

Leave command style at 0 when entering these commands manually; the control
panel detects the internal command and caches style 4 after the first use.
Behaviour reset restores the standard three-part layout and shows Spectrum.
Appearance reset restores the InfoStack tab strip.

Knob indicator colour provides:

Volume drag refresh rate
~~~~~~~~~~~~~~~~~~~~~~~~

Controls the visual refresh cadence used while dragging the knob.

Choices:
- Automatic (default)
- 8 ms
- 10 ms
- 12 ms
- 16 ms

Automatic follows the fastest live UI refresh interval reported by JS Playlist
and Smooth Playlist Manager. For example, if JS Playlist uses 8 ms and Playlist
Manager uses 16 ms, the knob preview uses 8 ms. When neither panel has reported
a value, Automatic uses a 16 ms fallback.

The knob preview is independent from the underlying fb.Volume write cadence.
Actual volume writes retain a safe minimum interval of 16 ms to avoid flooding
global volume-change callbacks and starving native visualisers. The first drag
value is immediate and the exact final value is flushed on release.

A manual choice overrides the preview cadence only; it does not raise the
volume-write frequency above the protected 16 ms maximum cadence.

DarkOne Tools
~~~~~~~~~~~~~

DarkOne Tools is available only from the optional TOOLS button described above.
Its top-level menu places Buttons immediately after Appearance for shorter
access to shared button appearance.

Appearance
~~~~~~~~~~

Bottom area background
- Transparent / inherit parent
- Black
- DarkOne grey (default)
- DarkOne dark grey
- Columns UI global background
- Custom colour (#RRGGBB)
- Set custom colour...

This single setting controls the bottom-left control panel, bottom-right control
panel, centre Display panel and the Bottom Controls JSplitter backing behind
them. Transparent / inherit parent resolves uniformly to DarkOne dark grey
(`#181818`, `DOJSP3.colours.separator`) across all three panels and both nested
JSplitter hosts. Literal no-paint transparency is not used because native JSP3
and JSplitter child windows expose different component backings. Columns UI mode
follows the current Columns UI global background and updates when the UI colour
changes.

Bottom area side divider colour
- Transparent / inherit background
- Black
- DarkOne grey
- DarkOne dark grey (default)
- Columns UI global background
- Custom colour (#RRGGBB)
- Set custom colour...

This setting controls both lower vertical divider strips together. Transparent
leaves the selected bottom-area background visible in their place. Quick Search
has independent frame and normal/error background settings and is not affected
by this divider-colour setting.

Bottom area depth
- Flat (default)
- Soft

Flat paints no top depth edge. Soft paints four rows at the top of the existing
surface: the first is black (`#000000`), the second is `#0F0F0F`, and the third
and fourth are derived 20% brighter from the selected Bottom area background,
with RGB channels clamped at 255. All four rows are painted inside the panel, so
positions and heights do not change. Depth is independent of the gradient: Soft
remains visible with either a solid or gradient background.

Background linear gradient
- Disabled (default)
- Enabled

When enabled, the three bottom columns paint the selected Bottom area background
from its chosen colour at the top to a colour 30% less bright at the bottom.
Nested JScript and JSplitter surfaces sample the same full-height gradient
coordinates instead of restarting the gradient within their own bounds, so
their edges remain visually seamless. The effect does not alter Bottom area
depth, the Bottom area side divider colour or Quick Search's independent frame.
Quick Search backgrounds remain independent when an explicit colour is chosen;
either Quick Search background set to Transparent / inherit parent reproduces
the matching slice of this gradient.

Bottom side dividers
- Enabled (default)
- Disabled

This toggle appears after a separator beneath Background linear gradient. When
disabled, both lower vertical divider strips are hidden while their selected
colour remains saved. Re-enabling the toggle restores both strips with that
same colour. It does not affect the upper Album Art/Spectrum dividers.

For both menus, Custom colour immediately reapplies the remembered custom value.
Set custom colour... opens the native picker and, when a different colour is
accepted, stores it and selects Custom. Cancelling or leaving the native picker
unchanged is non-destructive.

The shared properties are:
- DARKONEJSP3.BOTTOM.BACKGROUND.MODE
- DARKONEJSP3.BOTTOM.BACKGROUND.CUSTOM.COLOUR
- DARKONEJSP3.BOTTOM.BACKGROUND.LINEAR.GRADIENT
- DARKONEJSP3.BOTTOM.DIVIDER.MODE
- DARKONEJSP3.BOTTOM.DIVIDER.CUSTOM.COLOUR
- DARKONEJSP3.BOTTOM.SIDE.DIVIDERS
- DARKONEJSP3.BOTTOM.DEPTH

The JScript Panel and JSplitter component hosts keep separate panel properties.
DarkOneJSP3 therefore mirrors this state through a small runtime-generated file
at js_data\darkonejsp3.bottom-area-state.txt. The file is created and updated
automatically; it is not part of the release package and should not be edited.
The revisioned v5 state identifies the coordinated commit that produced it.
Persistent v1 state from the previous public release, including the former
DarkOneJSP3\shared\bottom-area-state.txt location, is migrated directly to v5
and the legacy file is retired after successful canonical persistence.

Each JScript panel reads and applies the shared state once during
initialisation, before its first paint. Live colour changes use a coordinated
visual commit so the participating JScript Panel and JSplitter surfaces switch
together instead of repainting in a visible sequence. Divider-only changes still
avoid rebuilding JScript button or Display rendering resources.

A short-lived commit marker is written to
js_data\darkonejsp3.bottom-area-command.txt with one shared apply timestamp.
Bottom Controls checks for active commits every 25 ms and relays the same target
time inside the JSplitter domain. One ordered scheduler also checks Quick Search
and View commands every 100 ms, and the canonical state fallback every 500 ms.
Failed canonical-state writes are logged with the target path and receive up to
eight bounded retries. Bottom Controls retains the applied revision while the
file is stale, repairs it after a bounded deadline and yields only to a provably
newer revision, preventing a failed write from flashing the previous appearance.

Factory reset uses a second short-lived runtime command file at
js_data\darkonejsp3.reset-command.txt. The same Bottom Controls timer checks
that command every 500 ms, consumes and removes it, then rebroadcasts the
established reset notification to all JSplitter controllers. Reset peers apply
their defaults locally; only the initiating panel publishes the single shared
bottom-area commit.

Smooth scrolling

- Set custom refresh interval...

Defaults:

- Smoothness divisor: 2
- Wheel throttle: 8 ms

- Scrollbar dragging row snapping: enabled
- Snapped wheel row step: 3

Select a fixed preset or enter a custom interval from 7-40 ms. Lower values can
look smoother on high-refresh displays but generate more UI work.

The playlist uses demand-driven repaint scheduling, so the selected refresh
interval governs both smooth-scroll animation updates and the coalesced paints
that display them, rather than waking the panel continuously at idle. Scrollbar
thumb dragging uses a dedicated latest-target frame loop with time-based
interpolation, allowing lower refresh intervals to render intermediate positions
between host mouse-move callbacks. Row-snapped dragging remains aligned to
playlist rows, while free-position dragging retains pixel offsets. The exact
cursor-derived destination is applied when the mouse button is released. Changes
are applied immediately, including to row-snap or free-scroll animation already
in progress. Visible-row title-format output is
cached across scroll
frames and invalidated when playlist contents, affected metadata rows, queue
state, playback state or column formatting changes. Playback-dependent fields
are reused within the same playback update, and clock-dependent fields are
refreshed once per second while static fields remain cached. Custom columns

8. Queue Viewer
---------------

Scripted Queue Viewer (recommended)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Use a JScript Panel 3 instance with the exact custom title:

  DOJSP3.Queue

Load the reset-aware project wrapper rather than the generic sample entry:

  DarkOneJSP3\jscript\DarkOneJSP3 - Queue Viewer.txt

Inside DarkOneJSP3 the wrapper uses a bidirectional, file-backed bridge owned by
DOJSP3.Root. JSplitter calls `plman.GetPlaybackQueueContents()` directly and
publishes only the current queue entries to
`js_data\darkonejsp3.queue-state.json`. The JScript Panel therefore avoids
playlist-wide `%queue_indexes%` discovery during normal theme use.

The bridge is writable as well as readable. Queue mutations are sent back to
DOJSP3.Root through versioned command/result files and executed by JSplitter
against the authoritative playback queue. Commands are tied to the queue
session and generation, so a stale command is rejected instead of being applied
to a queue that changed between the menu click and execution.

Queue editing commands:
- Skip to this track
- Remove item from queue
- Remove selected items from queue
- Move up
- Move down
- Move to top
- Move to bottom
- Clear playback queue
- Delete key: remove the current selection

Reordering preserves the relative order of multi-selected rows. Duplicate queue
occurrences are addressed by their queue positions, so removing one occurrence
does not remove every matching source item. Detached queue items whose source
playlist no longer exists remain reorderable because JSplitter retains their
live handles.

Selection and navigation:
- Click: select one row
- Click empty list space: clear selection
- Ctrl+click: toggle rows
- Shift+click: select a range
- Ctrl+Shift+click: add a range
- Ctrl+A: select all
- Up/Down: move the active selection
- Shift+Up/Down: extend the selection
- Home/End: first or last row
- Page Up/Page Down: move by the visible page
- Enter: show the source playlist item
- Double-click: skip playback to that queued track
- Escape: clear selection
- Delete: remove the selected queue entry or entries

Source and utility commands:
- Show source playlist item
- Skip to this track
- Play source item now
- Open containing folder
- Properties or Properties for selected items
- Copy item title or selected item titles
- Copy file path or selected file paths
- Item display title formatting...
- Re-scan playback queue

Skip to this track is queue-aware: DarkOneJSP3 removes only the queued entries
before the chosen position, advances through foobar2000's normal Next action and
leaves every later entry queued in its existing order. It is also the default
double-click action. Play source item now instead launches the source playlist
item directly and can clear the playback queue; use it only when that behaviour
is intended.

The script also appends Font size, Colours, Background Wallpaper and
Configure... from the shared page controls. Its Colours menu additionally
includes Selected background. It has no Selection mode submenu because queue
rows already represent explicit source playlist items.

Existing DarkOneJSP3 layouts whose Queue wrapper was saved inside the FCL are
recognised through the project queue bridge, so Selected background appears
without replacing the layout or manually reloading the current wrapper.

Standalone Enhanced Sample Library behaviour
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The same Queue Viewer implementation remains usable as a standalone enhanced
JScript Panel sample. Outside DarkOneJSP3 there is no JSplitter mutation bridge,
so the generic sample intentionally remains read-only and uses the incremental
`%queue_indexes%` fallback scanner. Previous queue-source playlists and the
active playlist are prioritised, results are published progressively, removals
and playback advance use targeted cached-source refreshes, and `%queue_total%`
allows a non-empty discovery scan to stop as soon as every queue position has
been found. An empty queue still requires a complete fallback scan because
JScript Panel 3 exposes no direct queue enumeration API.

Native Waveform Minibar menu
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

spacer, to open the component-owned menu:

- Track to prefer when showing waveform
- Switch to logarithmic scale
- Use half wave mode
- Enable anti-aliasing
- Halt minibar processing

Enable anti-aliasing is directly below Use half wave mode, is enabled by
default and persists independently of the existing component preferences.
Changing it immediately rebuilds the active cached waveform. Smoothing runs
only during cached bitmap generation, not during ordinary playback-position
paints at the selected FPS.

Configure opens the component preferences containing the waveform colours,
transparent background and playback frame rate. The patched component provides
25, 30, 50, 60, 100, 120 and 144 FPS choices. Lower values reduce animation
work; 60 FPS is a balanced starting point, while 100-144 FPS is intended for
users who prefer smoother motion on high-refresh displays.

The component's played/unplayed waveform colours remain component-owned
settings; see INSTALLATION.txt for the reference DarkOneJSP3 values. Transparent
mode uses an RGB colour key. On an unusually high-contrast backing, anti-aliased
edges may therefore show a fine pre-blended fringe; disabling anti-aliasing
restores the original hard-edged waveform.

13. Resetting DarkOneJSP3
-------------------------

Menu path: DarkOne Tools > Reset DarkOneJSP3

Reset this panel restores DarkOneJSP3-managed properties belonging to the panel
where the menu was opened.

Reset appearance settings... broadcasts appearance defaults to every
participating DarkOneJSP3 JScript Panel and JSplitter controller.

Reset behaviour settings... broadcasts behaviour defaults.

Reset all DarkOneJSP3 settings... restores both groups. Multi-panel resets show
a confirmation prompt.

Reset commands write explicit DarkOneJSP3-managed defaults before reloading the
panels. They do not merely reload panels or store null values. Generic upstream
sample customisation that DarkOneJSP3 does not own is preserved. Album Notes
cache files and downloaded provider data are also preserved.

The enhanced JS Playlist participates in behaviour and full resets for its
smooth-scrolling, refresh, throttle, row-step, snapping, render-cache and
performance-diagnostic options. Playlist Manager also resets those behaviour settings. Its filter visibility, filter
width, row height and alternating-row option belong to appearance. Full reset
additionally clears its saved scroll anchors. InfoStack appearance reset
restores the automatic font base scale to 100%, DarkOne dark grey page backing
and Black upper side dividers. Information-page appearance reset also disables
each page wallpaper, clears its custom path and restores Blur to off. Quick
Search honours the same reset scopes:
appearance resets sizing, font, icon, frame and colours; behaviour resets search
and result preferences. Tag definitions, history and favourites are preserved by
scoped resets and cleared only by the panel's explicit complete reset.

DarkOneJSP3 Changelog
=====================

v0.9.29 - Release hardening and runtime efficiency
--------------------------------------------------

- Fixed saved non-default bottom backgrounds being dependent on a later
  `on_colours_changed()` callback. Each JScript panel now resolves and applies
  the persisted background unconditionally before its first paint.
- Added a one-time bottom-area initialisation guard, preventing repeated resize
  callbacks from rereading the runtime state file or querying peer panels.
- Split shared bottom-area state changes into background and divider changes.
  Divider-only selections still update and persist shared menu properties but no
  longer rebuild control buttons, volume colours, Display colour caches or
  rendered Display images in the three JScript panels.
- Moved `DarkOneJSP3.DisplayWaveform.HideWhenStopped` from appearance reset
  defaults to behaviour defaults, alongside the new-track reveal delay.
- Kept visible bottom-area colour synchronisation at 100 ms while reducing the
  factory-reset command check to 500 ms through the same single host timer.
- Acknowledged processed factory-reset commands by removing the short-lived
  command file, with an empty-file fallback for hosts where removal is
  unavailable.
- Removed the obsolete JScript state-file sync function and snapshot state left
  over from the retired continuous-polling implementation.
- Fixed Album Art script unload explicitly disposing active normal and blurred
  Direct2D bitmaps in addition to cancelling pending wheel work.
- Expanded validation for first-paint persistence, one-time initialisation,
  divider-only efficiency, split waveform reset scopes, 100/500 ms bridge
  cadence, reset-command acknowledgement and Album Art bitmap disposal.
- Advanced Control Left to 3.0.20, Control Right to 3.0.25, Display to 3.0.23,
  shared bottom-area appearance to 0.2.5 and the release validator to 0.6.5.

v0.9.28 - Bottom-area fixed-mode regression correction
------------------------------------------------------

  background resolver, so only Transparent / inherit parent reaches the
  resolved DarkOne dark grey fallback.
- Restored consistent Black, DarkOne grey, DarkOne dark grey, Columns UI and
  Custom backgrounds across the bottom JScript panels, Bottom Controls host and
  Automatic Display/Waveform host while preserving v0.9.27 transparent
  inheritance.
- Expanded runtime validation to compare all six shared background modes across
  both component hosts and the Automatic Display/Waveform consumer.
- Advanced Control Left to 3.0.19, Control Right to 3.0.24, Display to 3.0.22,
  shared bottom-area appearance to 0.2.4 and the release validator to 0.6.4.

  to `js_data\darkonejsp3.bottom-area-state.txt`; v0.9.22/v0.9.23 state under
  `DarkOneJSP3\shared` is migrated automatically.
- Reduced continuous state polling from four readers at 250 ms to one Bottom
  Controls reader at 500 ms. The three JScript panels now read once during
  initialisation and use their same-component notification fast path.
- Fixed duplicate bottom-area appearance application so one peer state change
  causes one property application and one visual refresh.
- Added diagnostics for both thrown write failures and `WriteTextFile` returning
  false, including the target path, plus one delayed retry for bottom-area state.
- Removed obsolete BottomArea query/set/state handling and broadcasts from the
  Bottom Controls JSplitter left over from the failed cross-component transport.
- Aligned shared colour-menu command IDs so Columns UI uses base + 4 and Custom
  colour uses base + 5 in both JScript Panel and JSplitter helpers.
- Added package validation rejecting generated state and reset-command files,
  plus `.gitignore` rules for repository-backed portable profiles.
- Added isolated-host runtime tests for reset propagation, expired-command
  rejection, one-time command handling, write failure/retry, single repaint
  behaviour, legacy-state migration and sole-host polling.
- Updated the tested JSplitter version to 4.1.12.
- Advanced Control Left to 3.0.17, Control Right to 3.0.22, Display to 3.0.20,
  shared JSplitter protocols to 0.2.1, bottom-area appearance to 0.2.0 and the

v0.4.13 - AllMusic MusicBrainz fallback-state and timeout fix
-------------------------------------------------------------
- Fixed the main cause of intermittent silent relationship lookups: the
  mb_fallback_started one-shot guard was not reset when the focused album
  changed after a blocked or failed lookup. The next album could print "Trying
  MusicBrainz relationship lookup..." and return immediately without issuing a
  MusicBrainz request.

  outstanding request state on every artist/album change.

  resolver request so a genuinely missing JSP3 HTTP callback cannot hang
  forever.

  transport/HTTP failures (including 408, 425, 429 and 5xx responses).

- Added visible progress/retry/final-failure messages and precise console
  diagnostics. Timed-out task IDs are discarded so late callbacks are ignored.
- Clears pending watchdogs and delayed-request timers when the album changes,
  the object resets or either AllMusic panel unloads.

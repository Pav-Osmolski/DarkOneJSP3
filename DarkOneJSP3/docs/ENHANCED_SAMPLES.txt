Enhanced JScript Panel 3 Samples
================================

Purpose
-------
The user-components-x64 tree supplied with DarkOneJSP3 is now a standalone,
upgraded JScript Panel 3 sample suite. The enhanced samples no longer require
the DarkOneJSP3 project directory and can be used by other foobar2000 themes.

Installation outside DarkOneJSP3
--------------------------------
1. Close foobar2000.
2. Back up the installed foo_jscript_panel3\samples directory and helpers.txt.
3. Merge the supplied user-components-x64\foo_jscript_panel3 tree into the
   active profile's user-components-x64 location.
4. Load the desired top-level sample .txt file in a JScript Panel 3 instance.

The DarkOneJSP3 folder and its Columns UI layout are not required for standalone
sample use.

Compatibility design
--------------------
- Existing sample filenames, module filenames, constructors and import paths are
  retained.
- helpers.txt carries guarded performance and UI-cadence fallbacks so themes
  whose panel configuration still contains an older JS Playlist or Smooth
  Playlist Manager entry script continue to receive the globals now used by the
  upgraded internal modules.
- JS Playlist detects DarkOneJSP3 Quick Search `Search for same` metadata only
  when the project runtime bridge is present. Standalone use remains independent
  and does not acquire a Quick Search dependency or extra context menu.
- Current enhanced entries import reusable files from samples\shared rather
  than %fb2k_profile_path%DarkOneJSP3\shared.
- Existing DARKONEJSP3.*, JSPLAYLIST.* and SMOOTH.* property keys remain intact,
  preserving saved settings.
- The neutral JSP3Enhanced.Reset.Properties notification and the legacy
  DarkOneJSP3.Reset.Properties notification are both supported.
- darkonejsp3_reset.js is retained as a generated, self-contained legacy
  adapter containing the sample defaults and neutral reset bridge required by
  saved entries created before the standalone-sample refactor.
- enhanced_page_background is the neutral _panel option;
  darkonejsp3_page_background remains a supported alias.
- Participating information pages expose a shared Colours menu with Dynamic,
  Page background and Text controls. Dynamic uses the current artwork palette
  without overwriting the saved fixed choices.
- The same participating pages expose Playlist Manager-compatible Background
  Wallpaper controls for the playing front cover or an independent custom
  image, with optional blur and explicit native-resource cleanup.
- DarkOneJSP3's Queue wrapper additionally opts into Selected background; the
  generic standalone Queue entry retains its original selection appearance.
- The standalone Queue Viewer deliberately uses its JScript Panel
  `%queue_indexes%` discovery path and remains read-only. DarkOneJSP3's
  project-specific wrapper instead enables the direct, writable JSplitter
  queue bridge, while the component sample retains no project-folder runtime
  dependency.

Combined image layouts
----------------------
Last.fm Bio + Images.txt combines the hardened Last.fm Biography with downloaded
artist imagery. Its visible playing-artist view starts automatic acquisition
whenever artwork is needed, de-duplicates an active request and retries at a
bounded cadence. Successful downloads refresh the active artist immediately;
hidden panels skip periodic image work, and unload releases the image-cycle
timer, pending request maps and Direct2D bitmaps. Until an image is available,
the image region reports downloading, retry/error or confirmed-unavailable
status at its centre. Request, result, queue, file and completion diagnostics are
written to the JScript Panel console. HTTP failures include their status and
reason, response length, selected content/CDN headers and a short sanitised body
preview, making Last.fm's minimal 502 page distinguishable from gallery markup.
Transport failures, HTTP 408/425/429 and 5xx responses remain eligible for the
bounded retry cadence; permanent HTTP errors require Download now.

Gallery extraction supports the normal DOM path plus a raw-markup fallback for
current Last.fm image pages. An unrecognised response, such as a verification or
truncated page, is reported as unreadable and remains retryable rather than being
misclassified as an artist with no images. Non-2xx responses never enter the
gallery parser.

Album Notes + Album Art.txt combines the consolidated Album Notes providers with
the current album artwork. It preserves Album Notes source selection, caching,
MusicBrainz views and diagnostics while reusing Album Art's deferred blur and
resource-lifecycle implementation.

In both entries, right-click the image region to select a left/right or
top/bottom layout. Ctrl+wheel changes the image-to-text ratio. Ordinary wheel
input scrolls the text or cycles images when the pointer is over the relevant
region. Both combined titles reserve their full font height before the upper
scroll arrow, including at larger fonts and DPI. `header_gap = _scale(0)` is the
visually aligned baseline; increase it near the top of either combined entry to
add display-scaled spacing. A separate two-pixel control inset compensates for
the arrow glyph's built-in top padding. The Biography text region is bounded to
the visible panel in both orientations, keeping its lower scroll arrow visible
whenever additional text is available. Scrollable DirectWrite text now fades
linearly over a small display-scaled band at each edge where a scroll arrow is
visible. The scrolled layout is rendered once into a reusable transparent image
and composited through a cached continuous vertical alpha-gradient mask, keeping
high-DPI clipping smooth without repeatedly redrawing the full TextLayout for
every fade pixel. The fade changes only text alpha; the up/down arrow glyphs are
painted afterwards at full opacity. The same shared treatment is used by Album
Notes, its AllMusic provider, Last.fm Biography, Play Log, Console and Text
Reader, and styled Console colour ranges preserve their individual colours while
fading.

Both entries expose the enhanced Colours and Background Wallpaper menus. Their
Image background submenu independently enables the displayed artwork as the
full-panel backing, selects blur and Light/Medium/Dark shading, or disables it
to reveal the configured page colour or generic wallpaper. Display images or
Display album art hides the foreground image and collapses its region instead
of leaving empty space; right-clicking the text region still exposes the control
when it is hidden. Image border selects None, Solid or Sunken treatment and a
default or custom colour.

Last.fm Bio + Images places Hide if no images available directly below Download
now. When enabled, it collapses the image region only after a successful Last.fm
response confirms there are no usable images; network and parsing failures stay
visible, and a manual retry restores the region while it is in progress.

DarkOneJSP3 integration
-----------------------
DarkOneJSP3 uses these same standalone samples. Its project-specific code adds
layout coordination, InfoStack integration and coordinated factory-reset
commands, but the sample implementations and their shared runtime utilities
are owned by the JScript Panel component tree.

Validation
----------
The release validator stages user-components-x64 by itself, with no DarkOneJSP3
directory, and resolves every distributed sample entry import. It also checks
legacy helpers.txt fallbacks, neutral and legacy reset notifications, property
compatibility, the optional page-background alias and generic context-menu
routing without the colour helper loaded.
